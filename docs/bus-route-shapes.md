# 버스 도로 좌표의 준비

## 목적과 자료 선택

사용자는 진한 탑승 구간과 연한 전체 버스 노선이 도로를 벗어나는 문제를 개선하도록 요청했다. 정류장 사이를 직선으로 이으면 굽은 도로를 가로지르므로 실제 버스 노선의 도로 좌표가 필요하다. 임의의 곡선을 만들거나 일반 자동차 길찾기 결과를 실제 버스 운행 경로로 취급하지 않는다.

[경기도 버스노선 조회](https://www.data.go.kr/data/15080662/openapi.do)의 [노선형상정보](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRouteLine)와 [경유정류소](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBusRouteStation)를 대조한다. [공식 카탈로그](https://www.data.go.kr/catalog/15080662/openapi.json)에서 무료 제공·이용허락범위 제한 없음을 확인했다. 현재 자료와 노선 ID·정류장 위치·운행 순서가 맞는 경우에만 적용한다. 이름이나 노선 번호만 같은 다른 버스·반대 방향·새로운 분기로 연결하지 않는다.

API는 자료를 미리 준비할 때 사용한다. 앱은 GitHub Pages에 배포한 정적 좌표만 사용하며, 사용자 검색마다 외부 노선 API를 호출하거나 인증키를 브라우저에 배포하지 않는다. 준비 요청 수는 제한하고 결과를 재사용한다. 좌표가 없거나 검증되지 않은 노선은 정류장 연결선으로 유지해 실제 도로 경로로 오인하지 않게 한다.

서울·경기 전체의 도로 좌표 확보를 완료했다는 의미가 아니다. 이 서비스가 반환하고 현재 자료와 일치하는 노선부터 적용하며, 미확보 노선의 별도 출처 확보는 후속 과제다. 도로 좌표를 보완해도 KTDB 시간 추정의 기준일·정확도가 갱신되는 것은 아니다. [교통 자료 제약](search-data-setup.md)을 함께 따른다.

2026년 11월 2일 실제 일괄 수집에서 요청 횟수 제한 응답(`HTTP 429`, 제공기관 코드 `22`)을 확인했다. 무료 공개는 무제한 호출을 뜻하지 않으며 개별 승인 한도를 기준으로 한다. 한도에 도달하면 추가 수집을 중단하고 확보한 자료를 사용한다. 다음 자료 준비에서는 앞서 검사한 노선을 반복하지 않고 남은 범위부터 이어간다. 현재 확보 범위와 중단 사유는 [준비 보고서](../public/data/bus-shapes/audit.json)를 기준으로 확인한다.

## 파일 다운로드 대안 조사

2026년 11월 2일 사용자가 API 한도 대신 CSV·엑셀 등 다운로드 자료로 구현할 수 있는지 물었다. 경로 계산에 사용하는 기존 KTDB 자료는 계속 활용하되, 지도 표시를 보완할 때는 정류장 목록이 아니라 도로의 굴곡을 담은 경로점 자료가 필요하다. 파일 형식만으로 실제 버스 도로 선형이 포함됐다고 판단하지 않는다.

- [경기도 버스 노선 경로이력](https://www.data.go.kr/data/15124065/fileData.do): 공공데이터포털이 CSV·60만 행, 노선 ID·경로점 순서·X/Y 직교좌표·이력 ID 등을 안내한다. 무료·이용허락범위 제한 없음이며 실제 다운로드 제공처는 [경기데이터드림](https://data.gg.go.kr/portal/data/service/selectServicePage.do?infId=B87V4OBIG76T6N59I3SM33067357&infSeq=1)이다. 파일명은 `20230926`, 메타데이터 수정일은 2025년 7월 21일로 표기되어 있다. 수정일을 실제 좌표의 최신 기준일로 해석하지 않는다. 이력별 구분·좌표계·현재 노선과의 일치 및 서울 전체 포함 여부는 실제 파일 수령 후 확인해야 한다.
- [GBIS 기반정보 관리 매뉴얼](https://www.gbis.go.kr/gbis2014/publicService.action?cmd=mBaseInfo): 노선·정류소·노선별 정류소와 노선 형상 전체의 TXT 다운로드 주소·버전을 제공한다고 명시한다. [경기도 기반정보 관리](https://www.data.go.kr/data/15080658/openapi.do)는 [공식 카탈로그](https://www.data.go.kr/catalog/15080658/openapi.json)상 무료·이용허락범위 제한 없음이다. 버스노선 조회와 별개 서비스이므로 기존 활용 승인이 그대로 적용된다고 가정하지 않는다. 다운로드 주소·버전 조회에는 인증 API를 사용하며, 파일을 받은 뒤 각 노선의 좌표를 다시 API로 조회할 필요는 없다. 이 방식을 API 자체가 무제한이거나 전 과정 API 호출이 없는 방식으로 설명하지 않는다.

후속 자료 준비는 노선별 반복 조회보다 전체 파일 다운로드를 우선 검토한다. API를 전혀 사용하지 않고 수집하려면 CSV 제공을 이용할 수 있지만, 과거 이력으로 현재 노선을 잘못 연결해서는 안 된다. 파일을 가공해 정적으로 배포하면 앱의 노선 도로 좌표 조회에는 외부 노선 API가 필요하지 않다. Kakao 지도·장소 검색의 기존 사용 조건과 한도는 별개다.

이번 조사에서 공식 제공 명세·무료 여부는 확인했지만 실제 CSV·TXT 파일을 내려받아 반영한 것은 아니다. 경기데이터드림 상세 페이지는 조사 도구에서 시간 초과로 본문을 열지 못했다. 원본의 기준일·범위·실제 도로 형상과 기존 교통 자료를 대조하기 전까지 서울·경기 전체의 도로 이탈 문제가 해결됐다고 보고하지 않는다.

## 저장소 소유자의 최초 설정

1. [공공데이터포털](https://www.data.go.kr/)에 로그인한다.
2. [경기도 버스노선 조회](https://www.data.go.kr/data/15080662/openapi.do)를 열고 `활용신청`을 누른다. 활용 목적에는 `갈만집에서 버스 노선 도로 좌표를 미리 준비하여 정적 지도 경로로 표시`라고 입력하고 신청을 완료한다.
3. 마이페이지의 활용 신청 현황에서 해당 서비스가 승인되었는지 확인한다. 승인된 상세 화면에서 `일반 인증키(Decoding)`를 복사한다. 다른 API의 승인이나 Kakao JavaScript 키로 대체하지 않는다.
4. [저장소의 Actions 비밀 값 설정](https://github.com/hyeonjin-kim-dev/galmanzip/settings/secrets/actions)을 연다. 메뉴로 이동할 때는 `Settings` → `Secrets and variables` → `Actions` → `Secrets` → `New repository secret` 순서다. 이번 자료 준비는 GitHub Actions에서 실행하므로 이 위치의 Repository secret이 필요하다. 사용자가 선택했던 `Agents` 메뉴와 혼동하지 않는다. [GitHub 공식 안내](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets#creating-secrets-for-a-repository)를 참조한다.
5. `Name`에 `DATA_GO_KR_SERVICE_KEY`, `Secret`에 복사한 인증키를 입력하고 `Add secret`을 누른다. 인증키를 채팅이나 코드에 적지 않는다.
6. 에이전트에게 등록 완료를 알린다. 자료 준비 재실행·검증·커밋·배포는 에이전트가 진행한다. 사용자가 매번 `Run workflow`를 누르는 절차가 아니다.

신청서에 추가 필수 입력 항목이나 별도 이용 조건이 표시되면 해당 포털의 실제 안내를 확인한다. 승인 시점과 요청 한도를 추측해 보장하지 않는다. 위 절차는 자료 제공 API의 최초 승인·비밀 값 등록이며 별도 서버 운영을 요구하는 절차가 아니다.

## 에이전트의 후속 작업

- [자료 준비 워크플로](../.github/workflows/bus-shapes.yml)와 [준비 요청 예시](../config/bus-shapes-request.example.json)를 사용한다. 키 등록 후 에이전트가 예시를 실제 요청 파일로 작성해 푸시하거나 준비 작업을 실행한다. 자동 실행 조건·인자·요청 제한은 해당 파일을 기준으로 확인한다.
- [준비 코드](../scripts/prepare-bus-shapes.py)의 결과와 거부 사유를 확인하고, 받은 좌표를 실제 지도와 대조한다. 현재 노선과 일치하는지 확인하지 않고 API 응답 자체를 정답으로 단정하지 않는다.
- 성공한 실행의 `bus-road-shapes` 결과물을 검토하고 실제 자료만 [배포 좌표](../public/data/bus-shapes/)에 반영한다. 시험용 좌표를 공개 자료에 넣지 않는다. [좌표 검사](../tests/bus-shapes.test.ts)와 [준비 검사](../tests/test_bus_shapes.py)를 수행한 뒤 일반 배포 절차를 따른다.
- 실제 좌표 확보와 표시 기능의 준비를 구분해 사용자에게 알린다. 키가 없거나 자료 대조가 실패한 경우 도로를 따라 그리는 개선을 완료했다고 보고하지 않는다.
