# 검색 경험의 기준

## 결정 배경

사용자는 전체 검색의 진행 게이지를 기다리기보다 목적지 주변의 결과를 먼저 보고, 다른 지역은 뒤에서 계속 조회하기를 요청했다. 지도 이동·확대·축소는 새로 볼 지역을 정하는 동작이며 이미 확인한 목록을 지우는 이유가 되어서는 안 된다. 서울·경기 지원 범위 자체를 축소하는 결정은 아니다.

장소 조회와 경로 검증이 끝난 결과부터 사용할 수 있어야 한다. 빠르게 보이게 하려고 시간 조건·구간별 도보 제한을 완화하거나 검증 전 장소를 조건에 맞는 집으로 표시하지 않는다. 현재 지도에서 일치하는 집이 없을 수 있으며, 지도 밖의 확인된 집과 아직 조회 중인 상태를 구분한다.

사용자는 지도를 움직여야 목록이 갱신되는 것처럼 느껴지는 불편을 보고했다. 지도 조작 없이도 준비된 결과를 계속 사용할 수 있어야 하며, 다른 구역의 느린 응답 때문에 이미 확인할 수 있는 결과까지 기다리게 하지 않는다. 개선 효과는 같은 응답 지연·조회 범위에서 요청 수와 표시 시간을 함께 비교해 판단한다.

## 읽던 목록과 지도 유지

- 사용자의 최신 요청에 따라 무환승 결과는 지하철, 빨간 좌석버스, 기타 시내·마을버스 순으로 우선한다. 환승이 있는 결과는 무환승 결과 뒤에 표시한다. 늦게 발견되거나 지도를 넓혀 새로 보이는 집에도 적용한다. 도보 전용 결과를 버스나 지하철로 분류하지 않는다.
- 읽던 항목의 상세 펼침·포커스·스크롤을 유지하고, 각 수단 분류 안에서는 기존 순서를 보존해 새 결과를 뒤에 추가한다. 우선 수단의 결과가 늘었다는 이유로 이미 보던 항목이 페이지에서 빠지지 않게 한다.
- 사용자는 확대·축소할 때 목록이 늘었다 줄어드는 불편 때문에 한 번 표시한 집은 지도 밖으로 나가도 목록에 남겨 달라고 요청했다. 지도 이동에도 같은 원칙을 적용한다. 새로 보는 지역의 결과는 중복 없이 추가하고 기존 항목의 순서·상세·읽던 위치를 유지한다.
- 지도는 현재 화면의 집을 표시하며, 누적 목록과 지도 안 개수를 혼동하지 않게 한다. 목적지·시간·환승 조건을 바꾸거나 다시 검색할 때는 이전 검색의 목록을 초기화한다. 결과 유지는 현재 검색에 한정하며 사용자 정보를 영구 저장하는 기능으로 확대하지 않는다.
- 백그라운드 결과나 검색 완료를 이유로 지도 중심·확대 수준을 자동 변경하지 않는다. 목적지 중심 이동은 새 검색 시, 다른 지도 조작은 사용자 요청에 따라 수행한다.
- 긴 소요시간을 선택했을 때 목적지 바로 주변만 보여 결과가 적다고 오해하지 않도록, 목적지로 이동할 때 선택한 최대 소요시간에 맞춰 지도 범위를 단계적으로 넓힌다. 이후 사용자가 조정한 지도 범위는 계속 유지한다.
- 목록에서 선택한 집과 목적지의 위치 관계를 바로 확인할 수 있도록 항목 선택은 두 지점을 함께 보여 달라는 사용자 요청으로 취급한다. 고정 확대 수준보다 두 지점의 동시 노출을 우선하며 모바일 검색창·패널에 가리지 않게 한다. 같은 집을 다시 눌러도 이동할 수 있어야 하며, 경로 상세나 외부 링크 조작을 지도 이동으로 오인하지 않는다.
- 사용자는 지도에서 집이 모인 곳을 더 자세히 보는 동작과 목록에서 통근 경로를 보는 동작을 구분하도록 요청했다. 클러스터 선택은 그 지점 확대이며 목적지까지 다시 맞추지 않는다. 단일 집은 숫자 클러스터와 구별하고 정보창부터 확인할 수 있어야 한다. 지도 탐색만으로 읽던 목록을 지우거나 다른 경로를 선택하지 않는다.
- 지도상 거리와 대중교통 소요시간은 항상 같은 순서가 아니다. 무환승·수단 우선은 자동 적용하고 분류 안의 소요시간 재정렬은 사용자가 요청할 때 적용한다. 개별 아파트에서 환승 0회 경로를 먼저 찾는 원칙은 유지한다.
- 전체 검색 완료 전에도 목록·상세·지도 조작을 사용할 수 있어야 한다. 확인한 일부 결과를 전체 검색 완료로 표시하지 않는다.

## 예상 경로 표현

- 사용자는 소요시간을 수단별 게이지처럼 보여 주고 선택한 아파트의 경로를 지도에도 표시하기를 요청했다. 이 게이지는 기다려야 하는 진행률이 아니라 이동 시간의 구성이다. 도보·버스·지하철을 구별하고 색상만으로 정보를 전달하지 않는다. 이후 사용자가 승차 대기를 제외하도록 정했으므로 [소요시간 기준](routing-policy.md)을 게이지·상세에도 동일하게 적용한다.
- 사용자는 102번 같은 직행좌석버스를 빨간색으로 표시하고 버스 종류·지하철 노선에 따라 색상을 구분하도록 요청했다. 탑승 순서가 바뀌어도 같은 종류·노선의 색은 유지하며 게이지·상세·지도·연한 전체 노선을 일치시킨다. 같은 버스 번호가 여러 지역에서 사용되므로 번호만으로 종류를 추측하지 않고 원본의 분류를 따른다. 색만 보지 않아도 구분할 수 있게 종류·노선명을 함께 알리고, 밝은 배경에서도 시간을 읽을 수 있어야 한다.
- 제공 자료로 확인할 수 없는 요금·실시간 도착 시각은 이미지의 형식을 맞추려고 만들지 않는다. 지도 선형의 근거와 한계는 [자료 안내](search-data-setup.md)를 따른다.
- 지도에는 현재 선택한 경로와 그 경로에서 이용하는 버스의 전체 노선을 표시한다. 사용자는 버스 전체 노선을 연하게 표시하도록 요청했다. 탑승 구간과 구별하고, 이름이 같다는 이유로 다른 방향·분기 노선을 함께 표시하지 않는다. 지도 범위는 실제 이동 구간을 기준으로 유지해 버스의 종점 때문에 지나치게 축소되지 않게 한다.
- 사용자는 연한 전체 노선의 양 끝에서 기점·종점 이름을 확인하도록 요청했다. 왕복 노선은 마지막 정류장이 기점 근처로 돌아올 수 있으므로, 반대편 종점은 공식 파일의 운행 방향과 현재 정류장 순서가 일치할 때 표시한다. 확인되지 않은 회차 지점을 거리만으로 추측하지 않는다. 승차·하차 표시와 구분하고 기존 지도 범위 유지 원칙을 따른다.
- 사용자가 버스 경로의 도로 이탈을 개선하도록 요청했다. 검증한 실제 노선 좌표가 있으면 탑승 구간과 전체 노선에 같은 선형을 사용하고 출처·자료 일자를 알린다. 미확보 노선은 정류장 연결선임을 구별한다. 검색을 시작할 때 전체 도로 좌표를 준비하느라 기다리지 않게 하고, 선택한 노선만 준비한다. 실제 좌표의 확보 기준은 [도로 좌표 안내](bus-route-shapes.md)를 따른다.
- 선택 변경·검색 초기화 시 이전 경로와 버스 전체 노선이 남거나 늦은 응답으로 되살아나지 않아야 한다. 전체 이동 구간의 경유 지점이 보이도록 범위를 맞추되 사용자가 이미 지도를 조작했다면 늦은 경로 응답으로 위치를 되돌리지 않는다.
- 시각화를 위해 전체 검색과 목록 읽기가 느려지지 않아야 한다. 같은 검색에서 경로를 다시 선택하기 위한 메모리 재사용은 허용하지만 사용자 검색 기록의 영구 저장을 허용하는 것은 아니다.

## 검증과 참조

첫 결과의 표시와 전체 조회 완료 시간을 구분한다. 실제 교통 자료를 사용한 검증과 모의 장소 응답에서 얻은 시간을 실제 서비스의 속도 보장으로 확대하지 않는다. 반복 검색이나 지도 이동을 위해 사용자 데이터를 영구 저장하지 않는다.

구현은 [조회](../src/search/search.ts), [지도](../src/components/KakaoMap.tsx), [목록 상태](../src/search/view.ts), [목록 표시](../src/components/ApartmentResults.tsx)를 참조한다. 검증은 [목록 검사](../tests/view.test.ts), [영역 검사](../tests/zones.test.ts), [브라우저 검사](../tests/browser_viewport.py), [무환승 우선 검사](../tests/browser_priority.py)를 참조한다.

지도 이동 이벤트가 없는 상태의 자동 추가·응답 지연·읽던 위치 유지·요청 간격은 [자동 갱신 검사](../tests/browser_live_search.py), 응답 순서가 달라져도 후보를 누락하지 않는지는 [조회 구역 검사](../tests/planner.test.ts)를 기준으로 확인한다.

경로 표시는 [경로 좌표](../src/search/geometry.ts), [게이지](../src/components/RoutePreview.tsx), [좌표 검사](../tests/geometry.test.ts)를 참조한다. 지도 SDK 사용 근거는 [공식 Polyline 명세](https://apis.map.kakao.com/web/documentation/#Polyline)다.
