# 검색 경험의 기준

## 결정 배경

사용자는 전체 검색의 진행 게이지를 기다리기보다 목적지 주변의 결과를 먼저 보고, 다른 지역은 뒤에서 계속 조회하기를 요청했다. 지도 이동·확대·축소 시에는 화면에 보이는 영역의 집만 지도와 목록에 표시한다. 서울·경기 지원 범위 자체를 축소하는 결정은 아니다.

장소 조회와 경로 검증이 끝난 결과부터 사용할 수 있어야 한다. 빠르게 보이게 하려고 시간 조건·구간별 도보 제한을 완화하거나 검증 전 장소를 조건에 맞는 집으로 표시하지 않는다. 현재 지도에서 일치하는 집이 없을 수 있으며, 지도 밖의 확인된 집과 아직 조회 중인 상태를 구분한다.

## 읽던 목록과 지도 유지

- 추가 결과 때문에 이미 보던 항목의 순서·상세 펼침·포커스·스크롤을 바꾸지 않는다. 새 결과는 기존 목록 뒤에 추가한다.
- 사용자가 지도 영역이나 검색 조건을 바꾸면 해당 범위로 목록을 갱신한다. 지도를 넓힐 때도 계속 보이는 기존 항목의 순서는 보존한다.
- 백그라운드 결과나 검색 완료를 이유로 지도 중심·확대 수준을 자동 변경하지 않는다. 목적지 중심 이동은 새 검색 시, 다른 지도 조작은 사용자 요청에 따라 수행한다.
- 긴 소요시간을 선택했을 때 목적지 바로 주변만 보여 결과가 적다고 오해하지 않도록, 목적지로 이동할 때 선택한 최대 소요시간에 맞춰 지도 범위를 단계적으로 넓힌다. 이후 사용자가 조정한 지도 범위는 계속 유지한다.
- 목록에서 선택한 집과 목적지의 위치 관계를 바로 확인할 수 있도록 항목 선택은 두 지점을 함께 보여 달라는 사용자 요청으로 취급한다. 고정 확대 수준보다 두 지점의 동시 노출을 우선하며 모바일 검색창·패널에 가리지 않게 한다. 같은 집을 다시 눌러도 이동할 수 있어야 하며, 경로 상세나 외부 링크 조작을 지도 이동으로 오인하지 않는다.
- 지도상 거리와 대중교통 소요시간은 항상 같은 순서가 아니다. 읽기 안정성을 위해 이전의 자동 전체 재정렬 대신 사용자가 요청할 때 무환승·시간순 정렬을 적용한다. 개별 아파트에서 환승 0회 경로를 먼저 찾는 원칙은 유지한다.
- 전체 검색 완료 전에도 목록·상세·지도 조작을 사용할 수 있어야 한다. 확인한 일부 결과를 전체 검색 완료로 표시하지 않는다.

## 예상 경로 표현

- 사용자는 소요시간을 수단별 게이지처럼 보여 주고 선택한 아파트의 경로를 지도에도 표시하기를 요청했다. 이 게이지는 기다려야 하는 진행률이 아니라 이동 시간의 구성이다. 도보·대기·버스·지하철을 구별하고 색상만으로 정보를 전달하지 않는다.
- 제공 자료로 확인할 수 없는 요금·실시간 도착 시각은 이미지의 형식을 맞추려고 만들지 않는다. 지도 선형의 근거와 한계는 [자료 안내](search-data-setup.md)를 따른다.
- 지도에는 현재 선택한 경로만 표시한다. 선택 변경·검색 초기화 시 이전 경로가 남거나 늦은 응답으로 되살아나지 않아야 한다. 전체 경유 지점이 보이도록 범위를 맞추되 사용자가 이미 지도를 조작했다면 늦은 경로 응답으로 위치를 되돌리지 않는다.
- 시각화를 위해 전체 검색과 목록 읽기가 느려지지 않아야 한다. 같은 검색에서 경로를 다시 선택하기 위한 메모리 재사용은 허용하지만 사용자 검색 기록의 영구 저장을 허용하는 것은 아니다.

## 검증과 참조

첫 결과의 표시와 전체 조회 완료 시간을 구분한다. 실제 교통 자료를 사용한 검증과 모의 장소 응답에서 얻은 시간을 실제 서비스의 속도 보장으로 확대하지 않는다. 반복 검색이나 지도 이동을 위해 사용자 데이터를 영구 저장하지 않는다.

구현은 [조회](../src/search/search.ts), [지도](../src/components/KakaoMap.tsx), [목록 상태](../src/search/view.ts)를 참조한다. 검증은 [목록 검사](../tests/view.test.ts), [영역 검사](../tests/zones.test.ts), [브라우저 검사](../tests/browser_viewport.py)를 참조한다.

경로 표시는 [경로 좌표](../src/search/geometry.ts), [게이지](../src/components/RoutePreview.tsx), [좌표 검사](../tests/geometry.test.ts)를 참조한다. 지도 SDK 사용 근거는 [공식 Polyline 명세](https://apis.map.kakao.com/web/documentation/#Polyline)다.
