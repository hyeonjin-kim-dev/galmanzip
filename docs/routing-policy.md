# 경로 검색 원칙

## 결정 배경

2026년 11월 1일 사용자는 카카오 길찾기 API 사용 요청을 철회하고, 서버 없이 길찾기 알고리즘으로 구현하도록 명시했다. 이는 앞선 자체 계산 금지 결정을 대체한다. 무료 API의 호출량·인증 제약과 별도 서버의 운영 부담을 피하려는 선택이다. OTP·R5 서버나 서버리스 중계도 도입하지 않는다. Kakao 지도와 목적지·아파트 장소 검색은 기존 선택을 유지한다.

이미 전달받은 KTDB 자료를 활용한다. 출처와 자료의 한계는 [교통 자료 안내](search-data-setup.md)를 따른다. 가상의 교통 자료를 실제 서비스 결과로 제공하지 않는다.

## 무환승 우선 요구

- 사용자는 **환승 0회인 버스·지하철 경로를 반드시 먼저 찾을 것**을 요구했다. 더 빠른 환승 경로 때문에 이용 가능한 직통 경로가 사라져서는 안 된다.
- 우선순위는 선택한 최대 소요시간과 도보 제한을 충족하는 경로에 적용한다. 제한을 넘는 직통 때문에 조건을 지키는 환승 대안이 사라져서는 안 된다.
- 이름이 같은 노선이라도 차량을 바꾸어야 하면 무환승으로 취급하지 않는다. 반대 방향·다른 분기·승하차 금지 구간도 실제 이어지는 직통 경로로 오인하지 않는다.
- 최소 시간에 맞추려고 일부러 느린 우회 경로를 만들지 않는다. 우선 경로를 정한 뒤 선택한 시간 구간으로 결과를 거른다.
- 사용자가 목록을 읽는 동안 새 결과로 전체 순서를 바꾸지 않는다. 최신 결정에 따른 목록 안정성과 수동 정렬은 [검색 경험의 기준](search-experience.md)을 따른다. 경로 선택과 명시적 정렬의 기준은 [경로 계산 코드](../src/search/routing.ts)와 [회귀 검사](../tests/routing.test.ts)를 참조한다.

## 소요시간의 기준

사용자는 버스·지하철을 기다리는 시간을 경로에 포함하지 않도록 정했다. 이전의 승차 대기 포함 기준을 대체하며 검색 시간 구간, 경로 선택·정렬, 총 소요시간과 게이지·상세 표시 모두 같은 기준을 따른다. 대기 때문에 검색에서 탈락한 후보를 나중에 표시 시간만 줄여 복구하는 방식으로 처리하지 않는다.

승차 대기를 제외해도 승차·환승 횟수를 줄여 표시하지 않는다. 출발·도착·환승 도보와 차량에 탑승한 채 중간 정류장에 정차하는 시간은 계속 포함한다. 무환승 우선과 각 도보 구간 5분 제한도 유지한다.

## 도보 제한

사용자는 추가 답변에서 **집에서 정류장까지, 각각의 환승, 하차 후 목적지까지의 예상 도보 구간이 각각 5분 이하**라고 명확히 정했다. 앞선 전체 도보 합계 5분 해석을 대체한다. 출발 3분·도착 3분처럼 전체 도보가 5분을 넘어도 각 구간이 조건을 지키면 포함한다.

각 구간에서 정확히 5분은 포함하고 5분 1초는 제외한다. 차량을 타지 않고 계속 걷는 이동은 하나의 도보 구간이며, 정류장을 경유한다는 이유로 나누지 않는다. 빠른 경로가 도보 제한을 넘는다고 아파트를 바로 제외하지 말고 조건을 지키는 대안을 확인한다. 이는 보행망이 없는 추정 시간에 대한 조건이며 실제 도보 5분을 보장하는 결정은 아니다.

## 추정과 보관 제약

현재 단계는 출발 시각을 지정하지 않는 통근 가능성 탐색이다. 기준 자료의 평균 운행 시간과 보행 추정으로 최신 시간표·실시간 교통 상황·실제 보행 경로를 보장할 수 없다. 사용자가 제시한 10분 오차는 정확도 목표이며 검증된 보장 범위가 아니다. 자료에 없는 직통 노선을 반드시 찾는다고 주장하지 않는다.

같은 조건의 반복 계산을 줄이기 위해 자체 계산 결과를 두 시간 동안 화면의 메모리에서 재사용할 수 있다. 사용자 정보나 검색 기록의 영구 저장을 허용하는 결정은 아니다. 외부 장소 검색 응답의 장기 저장·재사용 허가로도 해석하지 않는다. 보관 조건은 [검색 코드](../src/search/search.ts), 실제 자료의 직통 경로 검증은 [자료 검사](../tests/data.test.ts)를 참조한다.

## 성능 검증 원칙

사용자는 초기 브라우저 검색이 매우 느렸다고 보고하고 성능 개선을 명시적으로 요청했다. 경로 계산만 빠르게 하는 데서 끝내지 않고 첫 결과가 나타날 때까지의 시간과 아파트 조회 완료까지의 시간을 구분해 확인한다.

- 실제 교통 자료로 비교하고, 모바일·iframe의 화면 조작과 취소가 계속 가능한지 확인한다. 재현용 [경로 측정](../scripts/benchmark-routing.ts)과 [브라우저 검사](../tests/browser_search.py)를 기준으로 검증을 이어간다.
- 속도를 위해 환승 0회 후보를 누락하거나 지원 지역을 몰래 좁히지 않는다. 장소 결과가 많은 지역은 제공 한도를 고려해야 하며, 조회량을 줄이면서도 후보 범위를 보존하는지 검사한다.
- 모의 장소 응답의 측정값을 실제 Kakao 서비스의 응답 속도나 전체 검색 완료 시간으로 보장하지 않는다. 최초 자료 준비와 재사용 시 계산 시간도 구분한다.
- [장소 검색 공식 명세](https://apis.map.kakao.com/web/documentation/#services_Places_keywordSearch)의 영역 조회와 [노출 한도](https://developers.kakao.com/docs/ko/local/dev-guide#search-by-keyword)를 확인했다. 제공 한도로 잘린 결과를 전체 확인으로 오인하지 않도록 알린다.
