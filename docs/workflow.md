# 개발 작업 흐름

## 커밋과 푸시

- 코드나 문서 수정이 의미 있는 작업 단위로 진행되면, 전체 작업이 끝날 때까지 미루지 말고 커밋하고 푸시한다.
- 커밋 전에 diff를 검토하고, 같은 목적이나 기능에 관련된 변경을 하나의 커밋으로 묶는다. 서로 무관한 변경은 별도 커밋으로 나눈다.
- 커밋 메시지는 한국어로 작성하며, 변경 내용과 목적을 명확하게 설명한다.
- 각 커밋 전에 변경에 필요한 검증을 수행하고 결과를 확인한다.
- 커밋 후 작업 브랜치를 원격 저장소에 푸시한다.
- 관련 없는 기존 변경은 임의로 포함하거나 되돌리지 않는다.
- 커밋이나 푸시가 실패하면 원인을 확인하고, 해결하지 못한 경우 실패 사실과 원인을 사용자에게 알린다.
