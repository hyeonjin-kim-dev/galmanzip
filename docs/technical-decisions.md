# 기술 방향과 데이터 조사

## 문서의 성격

2026년 10월 31일의 공식 자료 조사와 사용자 결정, 11월 1일 실제 교통 자료 검토 후 결정을 기록한다. 채택한 방향과 추가 검증이 필요한 사실을 구분하며, 구현 이후 코드에서 확인할 수 있는 구조·함수·설정값은 이 문서에 옮겨 적지 않는다. 외부 서비스의 요금·이용 조건은 변경될 수 있으므로 실제 연동 전에 원문과 발급받은 앱의 설정을 다시 확인한다.

## 확정된 제품 범위

- 첫 버전의 지원 지역은 **서울특별시와 경기도**다. 이전에 제안했던 서울 일부 지역 한정안으로 축소하지 않는다.
- 아파트 단지 정보와 매매·전세·월세 **실거래 내역**을 제공한다.
- 현재 판매·임대 중인 매물을 직접 제공할 필요는 없다. 매물 확인은 **네이버 부동산 외부 링크**로 연결한다.
- 사용자는 앞선 기술 제안을 위 범위에 맞춰 진행하는 것에 동의했다. 백엔드 서버 미운영, 사용자 정보 비저장, 비용 미지출 등 제품 원칙은 [프로젝트 개요](project-overview.md)를 따른다.

## 채택한 기술 방향과 이유

| 영역 | 선택한 방향 | 이유 |
| --- | --- | --- |
| 화면 | React + TypeScript + Vite로 정적 웹앱 개발 | 검색·지도·필터를 구성하고 GitHub Pages에 배포하며 향후 앱에서도 같은 웹앱을 재사용하기 위함 |
| 지도·목적지 검색 | Kakao Maps JavaScript SDK와 장소 검색 기능 | 선택한 지도 서비스를 유지하고 목적지를 좌표로 찾기 위함 |
| 전체 후보 탐색 | 공개 교통 자료로 교통망을 구성하고 브라우저에서 목적지 방향으로 역탐색 | 모든 아파트마다 외부 길찾기 API를 호출하는 비용과 한도 의존도를 줄이기 위함 |
| 계산 실행 | TypeScript와 Web Worker | 탐색 계산 중에도 지도와 화면 조작이 원활하도록 하기 위함 |
| 공간 검색 | 거리 계산과 격자 색인으로 시작하고 복잡한 공간 연산이 필요해지면 Turf.js·RBush 도입 검토 | 현재 필요한 거리·반경 판정만으로 외부 의존성을 줄이고, 규모에 따라 보완하기 위함 |
| 공개 자료 갱신 | 로컬 스크립트 또는 GitHub Actions에서 수집·변환 후 지역·기간별 정적 JSON 배포 | 운영 백엔드 없이 갱신하고, 사용자 브라우저에 공공데이터 인증키를 배포할 필요를 줄이기 위함 |
| 상세 경로 확인 | Kakao 지도 외부 길찾기 링크 | REST API 키를 공개 클라이언트에 추가하지 않고 사용자가 최신 경로를 확인하게 하기 위함 |

향후 상세 경로 API를 앱 안에서 사용하려면 무료 이용 조건과 브라우저·iframe 호출 검증이 선행되어야 한다. 외부 API 결과를 미리 수집해 교통망 데이터로 저장하는 방식은 전제로 삼지 않는다.

기술 참고: [Vite](https://vite.dev/guide/), [Web Worker](https://developer.mozilla.org/ko/docs/Web/API/Web_Workers_API), [Turf.js](https://turfjs.org/).

## 무료 이용과 저장 정책

- Kakao는 2026년 7월 21일 대중교통 경로 조회 API를 추가했다. 신규 앱의 무료 쿼터는 개발자 계정의 첫 번째 카카오맵 활성화 앱에 제공된다. [공식 공지](https://devtalk.kakao.com/t/api-notice-on-new-kakao-map-api-features-and-free-quota-policy/150222)
- [Kakao 쿼터 표](https://developers.kakao.com/docs/ko/getting-started/quota)에는 대중교통 경로 일 1,000건과 전체 API 월 300만 건이 안내된다. 한편 2026년 10월 6일 [공식 담당자 답변](https://devtalk.kakao.com/t/api-api/151980)은 유료 API 미설정 시 일간이 아닌 월 300만 건 정책이 적용된다고 설명한다. 실제 앱의 적용 한도를 확인하기 전에는 가능한 검색 횟수를 단정하지 않는다.
- 같은 담당자 답변은 대중교통 경로 결과의 별도 저장과 임시 캐싱을 허용하지 않는다고 안내한다. Kakao 결과를 미리 수집·저장해 호출 수를 줄이는 설계를 채택하지 않는다.
- [ODsay Basic](https://lab.odsay.com/contact/contact)은 일 30회, [TMAP 대중교통 FREE](https://transit.tmapmobility.com/)는 경로 API 일 10회로 안내되어 주된 전체 후보 탐색 수단으로 채택하지 않는다.
- ODsay에 [대중교통 접근성 영역 API](https://lab.odsay.com/guide/releaseReference?platform=web)가 있으나, 공개 명세는 특정 지점에서 출발해 도달하는 영역이다. 목적지로 도착 가능한 출발지를 구하는 기능으로 그대로 대체하지 않는다.
- [GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions)는 공개 저장소의 표준 GitHub 호스팅 실행 환경에서 무료다. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)는 배포 사이트 크기 1GB, 월 대역폭 100GB의 소프트 한도 등 제약이 있으므로 데이터를 필요한 지역·기간별로 나눠 제공한다.
- 과금형 상품이나 무료 한도 초과 과금에 의존하지 않는다. 한도 소진 시 기능 제한을 안내할 수 있도록 설계한다.

## 경로 판정 기준과 개발 순서

- 이동 방향은 **아파트 → 목적지**다. 목적지에서 출발하는 경로의 시간을 그대로 대신 사용하지 않는다.
- 도보·대기·탑승·환승·하차 후 도보를 합한 예상 총 소요 시간으로 판정한다. 정류장까지의 직선거리나 임의 반경은 후보 검색에만 쓰며, 실제 보행시간의 보장으로 표시하지 않는다.
- 사용자는 향후 검색 시 소요시간의 오차범위를 10분으로 정했다. 검색 판정 기능을 구현할 때 이 결정을 반영한다.
- 위 10분은 정확도 목표다. 검증 없이 실제 오차가 10분 이내라고 보장하지 않는다. 최대 소요시간에 임의로 10분을 더해 범위 밖의 결과를 포함하지 않으며, 실제 길찾기에서 확인하도록 안내한다.
- 평균 이동시간을 사용하는 초기 탐색에는 역방향 다익스트라 방식을 적용한다. 시간표 기반의 정확한 탐색은 운행일·시간대·급행·배차·환승 정보까지 확보해야 하며 별도 검증이 필요하다.
- 개발은 지하철 경로를 먼저 검증한 뒤 버스를 확장하는 순서로 진행한다. 이는 개발 순서이며 첫 버전의 지원 지역을 서울 일부로 줄이는 결정은 아니다.
- 공개 자료의 범위와 품질이 충분한지 확인하고, 지원하지 않는 노선이나 추정의 한계가 있다면 사용자에게 명시한다. 자료가 확보되지 않은 교통편을 지원한다고 표시하지 않는다.

## 후속 검증 과제

- 수령한 KTDB 자료에서 빠진 지역·운행 패턴 보완과 이후 개통·폐지·변경 사항의 갱신
- 아파트 좌표의 출처, 단지와 실거래 자료의 연결 정확도, 거래 정정·해제 반영 및 갱신 기준 검토
- 초기 평균 시간 추정과 실제 출발 시각의 길찾기 결과 비교, 보행망·운행일·시간표를 반영하는 후속 기준 검증
- 네이버 부동산 외부 링크의 실제 동작과 검색·단지 연결 방식 검증. 공개적으로 확인한 URL만 사용하며, 확인하지 않은 단지 식별자나 연결 규칙을 추측하지 않음
- Kakao 무료 쿼터 적용, 브라우저 및 iframe에서 경로 API 호출 시 CORS와 인증 방식 검증. 아직 발급 키를 이용한 실제 호출 검증은 하지 않음
- 정적 웹앱에 포함되는 값은 사용자에게 노출되므로 비밀키를 번들에 포함하지 않음. 공공데이터 인증키는 배포 전 수집 과정에서만 사용하고 결과 데이터에 남지 않는지 확인

관련 근거: [CORS](https://developer.mozilla.org/ko/docs/Web/HTTP/Guides/CORS), [Vite 환경변수의 클라이언트 노출](https://vite.dev/guide/env-and-mode). 서버에서만 사용 가능한 비밀키나 브라우저 호출이 허용되지 않는 API를 만나면 클라이언트만으로 처리 가능하다고 가정하지 않고 데이터 경로를 재검토한다.

## 검색 구현을 위한 추가 조사와 결정

- 교통망의 우선 확보 대상으로 KTDB 전국 GTFS 기반정보를 선택했다. 서울 일부 노선만으로 전체 지원을 주장하는 일을 피하기 위해서다. 사용자가 전달한 자료의 복원과 설명서 검토를 완료했다. 기준일·품질 제약·이용 근거는 [교통 자료 안내](search-data-setup.md)를 참조한다.
- 서울·경기 아파트의 통근 경로가 행정 경계에서 끊기지 않도록 인천의 연결 노선도 교통망에 포함한다. 아파트 지원 지역을 인천으로 확대하는 결정은 아니다.
- 현재 요청한 경로·목록 연결 단계에서는 [Kakao 장소 검색](https://apis.map.kakao.com/web/documentation/#services_Places_keywordSearch)으로 아파트 위치를 조회한다. 실거래가의 수집·단지 연결을 기다리지 않고 위치와 외부 매물 확인부터 제공하기 위한 단계적 결정이며, 실거래가 제공 목표를 없애는 결정은 아니다.
- 장소 검색은 전체 아파트 명부가 아니며 제공 결과와 페이지 한도가 있다. 누락 가능성을 알리고, 조회 실패나 중단으로 얻은 일부 결과를 전체 검색 완료로 표시하지 않는다. 실제 교통망으로 확인한 장거리 검색은 장소 조회 범위가 매우 넓다. 이 단계에서는 결과를 먼저 보여주고 중단할 수 있게 하되, 후속으로 공공 아파트 좌표 명부를 확보해 호출량을 줄이는 과제를 유지한다.
- 출발 시각을 입력받지 않는 현재 단계의 경로는 평균 시간 추정이다. 정적 자료의 보행 추정에는 강·도로·출입구·통행 제한이 반영되지 않을 수 있다. 경로를 실제 이용 가능한 최단 경로로 보장하지 않으며, 도보망과 시간표 기반 검증을 후속 과제로 남긴다.
- 위치·검색어·결과는 해당 화면의 메모리에서만 다룬다. 검색할 때 Kakao 장소 검색 서비스로 질의가 전달된다는 외부 연동 특성은 사용자 정보의 자체 저장 여부와 구분한다.
- 네이버 부동산의 공식 진입 주소와 카카오의 [외부 대중교통 길찾기 형식](https://developers.kakao.com/docs/ko/kakaomap/rest-api)은 확인했다. 확인하지 않은 네이버 개별 단지 주소를 만들지 않는다.
